`frontend/public`, and the sample content has no images. The only third-party graphic and font material is listed below.

## App icon

`frontend/app/icon.png` (512 by 512) and `frontend/app/apple-icon.png` (180 by 180) are the site owner's avatar picture, cropped to the
figure and resized with `sharp`. Next.js's App Router file convention serves them as the favicon and the iPhone home-screen icon.
They are **not** drawn for this project and are **not** under the MIT license: they belong to the owner of this instance and their
origin is the owner's responsibility. The previous neutral icon was a hand-written `icon.svg`; the clean release snapshot must carry a
neutral icon again (replace both files with your own, or restore `icon.svg` from git history and delete the PNG files), because
`e2e/golden-urls.spec.ts` expects `/icon.png` and `/apple-icon.png` and `app/opengraph-image.test.ts` checks their sizes. If you
rebrand your instance, replace the two files with square PNGs of the same sizes.

## Fonts

- **The site font is Inter**, loaded in `frontend/components/RootShell.tsx` with `next/font/google` (subsets `latin`, `latin-ext`
  and `vietnamese`, `display: 'swap'`). Inter is licensed under the SIL Open Font License 1.1, which allows use, embedding and
  redistribution.
- **The build needs network access to Google Fonts.** `next build` downloads the Inter font files from `fonts.googleapis.com` and
  `fonts.gstatic.com` once, at build time, and writes them into the build output. A machine that builds the frontend image (or
  runs `npm run build`) must be able to reach those hosts. A build with no internet access fails at the font step.
- **Readers' browsers never contact Google.** The built site serves the font files itself, from the site's own origin, so there is no
  request to a font CDN and no third-party font tracking.
- **Share cards** (the Open Graph image of a post, `/api/og/...`) use the default font that ships inside Next.js's `next/og`
  (Geist, OFL 1.1). The code loads no font file for them: that face covers the Vietnamese range, and fetching a font at render time
  would put a network call on the path of a crawler's image request (see the comment in `frontend/components/og/ShareCard.tsx`).
- If you need a build without network access, vendor the font files and switch to `next/font/local`; that is a code change and not
  a setting.

## Icons and brand marks

The interface uses no icon library at run time. The glyphs are inline SVG drawn on the server, with the path data copied from
`lucide-static` (ISC license; a few glyphs originate from the Feather project, MIT), and the license text is kept verbatim in
`frontend/components/icons.tsx`. The GitHub, Facebook, X and LinkedIn marks in `frontend/components/BrandIcon.tsx` come from
`simple-icons` (CC0-1.0). Those marks are trademarks of their owners; they are used only to point to a profile on that platform
and to share to it.

## Sample content

The sample posts (two pairs of English and Vietnamese posts, a series, a category and two tags) are Markdown files under
`backend/src/main/resources/sample-content/en/` and `.../vi/`. They were **written for this project**, explain the product in plain
words, contain no image and no text copied from elsewhere, and are released under the same MIT license as the code. An ADMIN loads
them from **Admin > Settings** (or with `POST /api/v1/admin/sample-content`); loading twice creates nothing new.

The default site content (placeholder name, tagline, profile, sections) in `frontend/content/defaults` and the packaged template
example `backend/src/main/resources/site-import/defaults-vi.json` is likewise neutral placeholder text written for this project.
It describes no real person.

Vietnamese text lives only where the English guard allows it: `sample-content/vi/`, `messages/vi.json`, `frontend/content/`,
`docs/vi/` and a few test fixtures ([CONVENTIONS.md](CONVENTIONS.md), section 4).

## Test fixtures

`backend/src/test/resources/media/` holds a few tiny images (a CMYK JPEG, rotated JPEG and WebP files, PNGs with and without a
display-P3 profile and alpha). `generate-fixtures.cjs` in that folder creates them with `sharp` (a coloured patch in one corner, so
the tests can prove the rotation direction). They are not photographs, they are used by `mvn test` only, and they are not part of
the Docker images.

## Screenshots

`docs/screenshots/*.png` are screenshots of a running instance that has only the packaged sample content and the neutral defaults.
They show no real person, no third-party image and no secret. Each image is referenced from [README.md](../README.md) with a
caption that states the viewport and the date it was taken. Re-take them when the design changes.

## Runtime requests to third parties

- **GitHub avatars.** A reader who signed in with GitHub has a profile picture served from `avatars.githubusercontent.com`. The
  reader's browser requests it from GitHub directly (128 px). Nothing else loads from a third-party host. A site with GitHub
  sign-in off never requests one.
- **No analytics, no ads, no third-party script, no web font CDN.**

## Adding an asset

Before you add an image, a font or an icon: check that its license allows redistribution under the project license, keep the
license text or notice next to it (as `icons.tsx` does), and add a row to the table above. Do not add a photograph of a real
person or an image you cannot trace to a license. Never commit a file named after a person, an employer or a private address.
